TB520FU · codename lapis

What the port actually boots.

Silicium starts from slot A. GRUB loads the kernel and the board device tree from the boot filesystem. The root is an ext4 volume labeled eos-lapis. There is no initramfs. Slot B keeps the Android boot image.

Boot path

  1. The bootloader on boot_a is a Mu-Silicium RELEASE image. dtbo_a is erased so the Android overlay is not applied. vbmeta_a is the stock image with verity and verification disabled.
  2. Silicium reads the EFI system partition on pstoredump. That volume is FAT16 with 4096-byte sectors. GRUB is EFI/BOOT/BOOTAA64.EFI.
  3. GRUB loads /Image and /dtbs/qcom/sm8650-lenovo-tb520fu.dtb from lenovocust, the ext4 filesystem labeled boot.
  4. The kernel command line from the current image builder is root=LABEL=eos-lapis rw rootwait console=tty0 quiet splash.

pstoredump and lenovocust are shared by both slots. The Linux images replace whatever those two partitions held. boot_b, dtbo_b, and the signed vbmeta_b stay as Android left them.

From Linux, qbootctl -s b and a reboot select Android. From fastboot, fastboot set_active b does the same and clears the successful flag. After a Linux boot, the image runs qbootctl -m and marks the booted slot successful.

flash.sh writes those four partitions and leaves slot B and userdata alone. The install guide also erases dtbo_a and writes the disabled-verity flags to vbmeta_a. Those two are not in flash.sh.

Devices

SM8650P

Snapdragon 8 Gen 3. The device tree is sm8650-lenovo-tb520fu.

Tianma NT36532

Dual-DSI, 2944×1840. Touch and the pen are on the same panel.

WCN7850

Wi-Fi and Bluetooth. The factory addresses come from persist.

Cameras

Rear GC13A0. Front GC13A2.

Lenovo-TB520FU

Six AW88461 amplifiers. The card name, UCM, and topology stay Lenovo-TB520FU.

Pen and folio

The pen module is lenovo_tb520fu_pen. Closing the folio blanks the screen.
