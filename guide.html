Install Hardware Kernel Packages

Install

Unlock, carve arch, flash slot A.

Linux lives on boot_a. Android’s boot image stays on boot_b. The root filesystem is a new partition named arch, cut from userdata. The flasher does not write userdata or slot B.

Before you start

Unlocking the bootloader erases Android’s data. Copy files off the tablet first.

Do not flash boot_b, userdata, vbmeta_b, dtbo_b, xbl, abl, persist, fsg, modemst1, or modemst2.

fastboot set_active clears the successful flag. Run it only when the current slot is not already a, and do not run it again after Linux has booted.

The UFS logical sector size is 4096 bytes. sgdisk on this disk counts in those sectors. A worked example below belongs to one tablet. Another disk needs its own start and end.

Unlock the bootloader

  1. On ZUI, open Settings, About tablet, and tap Software version until developer options turn on. In General settings, Developer options, turn OEM unlocking on. The tablet needs Wi-Fi for that switch.

  2. Reboot to fastboot and read the serial. It is the short alphanumeric string on the fastboot screen, usually eight characters.

    adb reboot bootloader
fastboot devices
fastboot getvar serialno

  3. On the computer, download unlock-bootloader.py and build the image for that serial. The script writes sn_<serial>.img and prints the fastboot lines.

    python3 unlock-bootloader.py YOURSERIAL
fastboot flash unlock sn_YOURSERIAL.img
fastboot flashing unlock

    Confirm on the tablet with the volume keys and the power button. If this bootloader rejects flashing unlock, use fastboot oem unlock-go.

  4. Let ZUI boot once so it can recreate userdata. Then continue with the partition step.

Carve the arch partition

This keeps Android’s data on a smaller userdata and adds partition 17, named arch, for the Linux root. The edit is done from a TWRP shell. This site does not host a TWRP image.

TWRP’s own toolbox does not provide sgdisk. The carve used for this port runs a real sgdisk and mkfs.ext4. Check sgdisk --version before you delete any partition.

  1. Boot TWRP. On this tablet the disk node used for the carve is /dev/sda. If that path is missing, use /dev/block/sda. Back up the GPT, then print partition 16 and write down its start and end.

    sgdisk --backup=/tmp/sda-gpt.bak /dev/sda
sgdisk -i 16 /dev/sda
sgdisk -p /dev/sda

    Copy /tmp/sda-gpt.bak off the tablet before you continue. A backup that stays in /tmp dies with the recovery session.

  2. Compute the cut in 4096-byte sectors. 100 GiB is 26214400 sectors. The start of userdata stays where it is.

    new_userdata_end = old_end - 26214400
arch_start       = new_userdata_end + 1
arch_end         = old_end

    Stop if those numbers are outside the current userdata range, or if fewer than about 32 GiB would remain for Android.

    Worked example from the tablet this port was brought up on. These numbers matched that disk only. userdata was 5972392..60884986. After a 100 GiB cut, userdata became 5972392:34670586 and arch became 34670587:60884986.

  3. Rewrite partition 16 and create partition 17. Substitute your own start, end, and arch range. The type code 8300 is a Linux filesystem.

    sgdisk \
  -d 16 \
  -n 16:USERDATA_START:NEW_USERDATA_END -c 16:userdata \
  -n 17:ARCH_START:ARCH_END -c 17:arch -t 17:8300 \
  /dev/sda
sgdisk -p /dev/sda

    Ask the kernel to reread the table (blockdev --rereadpt /dev/sda) and confirm the new arch node exists. The next flash writes a filesystem image over it.

Flash slot A

The image zip contains silicium.img, endeavouros_esp.raw, endeavouros_boot.raw, endeavouros_rootfs.raw, and flash.sh. flash.sh writes the four partitions below and asks you to type yes. It does not call set_active.

fastboot devices
fastboot flash boot_a silicium.img
fastboot flash pstoredump endeavouros_esp.raw
fastboot flash lenovocust endeavouros_boot.raw
fastboot flash arch endeavouros_rootfs.raw
fastboot erase dtbo_a
fastboot --disable-verity --disable-verification flash vbmeta_a vbmeta_stock.img

vbmeta_stock.img is a copy of the signed stock vbmeta, the same bytes that stay on vbmeta_b. The flags are applied to vbmeta_a only. dtbo_b stays.

Read the current slot. If it already prints a, leave it. If it prints b, switch once:

fastboot getvar current-slot
fastboot set_active a

That switch clears the successful flag. The image marks slot A successful after the first Linux boot.

First boot

Wait until the Silicium menu is on screen and Internal Storage is highlighted. A short press of the power button is Enter and continues the boot. A long press resets. From GRUB, a long press returns to fastboot.

The image locks the root password and does not create a desktop user. SSH accepts the public key the builder installed for root. Over USB the tablet is 172.16.42.1. The hostname is lapis. Add your own user after that login.

Android’s boot image is still on slot B. Select it from fastboot with fastboot set_active b, and come back with fastboot set_active a. Each switch clears the successful flag.

Do not switch slots from Linux. qbootctl -s moves the active flag without the partition type GUIDs. The bootloader then refuses every boot and the tablet stays in fastboot until the partition table is repaired over EDL.
