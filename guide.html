Install Hardware Kernel Packages

Install

Unlock, then pick where the root filesystem goes.

Both paths flash the same UEFI, EFI, and kernel images to slot B. Multiboot keeps a shrunk Android data partition and adds one named arch. The other path writes Linux over userdata and does not edit the partition table.

Path A Multiboot TWRP, then a new arch partition, then flash. Path B Whole userdata No repartition. The root image replaces Android’s data.

Before either path

Unlocking the bootloader erases Android’s data. Copy your files off the tablet first.

Linux is flashed to boot_b. Leave boot_a alone if you still want Android’s boot image.

pstoredump and lenovocust are shared, not A/B. The EFI and kernel images replace them.

Do not flash xbl, abl, vbmeta, persist, fsg, modemst1, or modemst2.

The UFS logical sector size is 4096 bytes. sgdisk on this disk counts in those sectors.

Unlock the bootloader

  1. On ZUI, open Settings, About tablet, and tap Software version until developer options turn on. In General settings, Developer options, turn OEM unlocking on. The tablet needs Wi-Fi for that switch.

  2. Reboot to fastboot and read the 8-character serial printed on the screen.

    adb reboot bootloader
fastboot devices
fastboot getvar serialno

  3. Request sn.img from Lenovo’s tablet unlock portal with that serial. The file is signed for one device. This site does not host it. When you have the file:

    fastboot flash unlock sn.img
fastboot flashing unlock

    Confirm on the tablet with the volume keys and the power button. If this bootloader rejects flashing unlock, use fastboot oem unlock-go.

  4. Let ZUI boot once so it can recreate userdata. Then continue with path A or path B.

Path A — multiboot from TWRP

This keeps Android’s data on a smaller userdata and adds partition 17, named arch, for the Linux root. The repartition is done from a TWRP shell on recovery_b. This site does not host a TWRP image.

TWRP’s own toolbox does not provide sgdisk. The carve used for this port runs a real sgdisk and mkfs.ext4 (an Alpine aarch64 build unpacked where the recovery can execute it). Check sgdisk --version before you delete any partition.

  1. Boot TWRP. On this tablet the disk node used for the carve is /dev/sda. If that path is missing, use /dev/block/sda. Back up the GPT, then print partition 16 and write down its start and end.

    sgdisk --backup=/tmp/sda-gpt.bak /dev/sda
sgdisk -i 16 /dev/sda
sgdisk -p /dev/sda

    Copy /tmp/sda-gpt.bak off the tablet before you continue. A backup that stays in /tmp dies with the recovery session.

  2. Compute the cut in 4096-byte sectors. 100 GiB is 26214400 sectors. The start of userdata stays where it is.

    new_userdata_end = old_end - 26214400
arch_start       = new_userdata_end + 1
arch_end         = old_end

    Stop if those numbers are not inside the current userdata range, or if fewer than about 32 GiB would remain for Android. A disk with a different userdata range needs its own arithmetic. Pasting another tablet’s sectors here will delete the wrong span.

    Worked example from the tablet this port was brought up on. These numbers matched that disk only. userdata was 5972392..60884986. After a 100 GiB cut, userdata became 5972392:34670586 and arch became 34670587:60884986.

  3. Rewrite partition 16 and create partition 17. Substitute your own start, end, and arch range. The type code 8300 is a Linux filesystem.

    sgdisk \
  -d 16 \
  -n 16:USERDATA_START:NEW_USERDATA_END -c 16:userdata \
  -n 17:ARCH_START:ARCH_END -c 17:arch -t 17:8300 \
  /dev/sda
sgdisk -p /dev/sda

    Ask the kernel to reread the table (blockdev --rereadpt /dev/sda) and confirm the new arch node exists. You do not format it by hand when the next step flashes a filesystem image over it.

  4. Reboot to fastboot and flash the four images from the image build. flash.sh in that build runs this same sequence and asks you to type yes.

    fastboot devices
fastboot flash boot_b silicium.img
fastboot flash pstoredump endeavouros_esp.raw
fastboot flash lenovocust endeavouros_boot.raw
fastboot flash arch endeavouros_rootfs.raw
fastboot set_active b
fastboot reboot

Android’s boot image is still on slot A. fastboot set_active a, or qbootctl -s a from Linux, selects it.

Path B — the whole userdata partition

Skip TWRP and skip the partition edit. The root image is written to the existing userdata partition. That destroys Android’s data. The partition’s GPT name can stay userdata. The filesystem inside the image is labeled eos-lapis, which is the label GRUB boots.

flash-multiboot.sh asks for the root partition name and, if you answer userdata, asks you to type userdata again before it writes.

fastboot devices
fastboot flash boot_b silicium.img
fastboot flash pstoredump endeavouros_esp.raw
fastboot flash lenovocust endeavouros_boot.raw
fastboot flash userdata endeavouros_rootfs.raw
fastboot set_active b
fastboot reboot

The root image has to be smaller than the userdata partition. The image builder sizes that file to the installed system, so it fits. Slot A’s boot image is still there, and Android no longer has its data partition.

First boot

Silicium opens on its menu with Internal Storage highlighted. A short press of the power button is Enter and continues the boot. A long press resets.

GNOME runs its initial setup. The root password is root. The hostname is lapis. Over USB, the tablet is at 172.16.42.1.
